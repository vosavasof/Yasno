# Ясна в Яндекс Cloud

Подготовлен общий Node.js-сервер: приложение и API на одном домене, SQLite на постоянном диске, файлы чеков и ключи в Docker volume. HTTPS обслуживает Caddy. Публичны только 80/443; SSH ограничен вашим IP. Нет зависимости от прежнего облачного API.

Нужны аккаунт Яндекс Cloud с биллингом, каталог (folder ID), домен и открытая часть SSH-ключа. План создаёт платные VM (2 vCPU/2 ГБ, доля CPU 20%), SSD 20 ГБ, статический IPv4 и сеть в российском регионе. Стоимость проверьте в актуальном калькуляторе Яндекс Cloud. Подготовка файлов ничего не создаёт и не списывает.

1. Войдите в Яндекс Cloud через `yc init` на своём компьютере/Cloud Shell. Токены и приватные ключи не отправляйте в переписку и не коммитьте.
2. Установите Terraform, скопируйте `terraform.tfvars.example` в `terraform.tfvars` и укажите свои значения. Приватный SSH-ключ сюда не добавляется.
3. Передайте авторизацию провайдеру в своём терминале: `export YC_TOKEN="$(yc iam create-token)"`. Затем `terraform init` и `terraform plan -out=work.tfplan`.
4. Проверьте план и стоимость. Только после этого выполните `terraform apply work.tfplan`.
5. В DNS домена добавьте A-запись на `public_ip` из вывода. После распространения DNS Caddy получит сертификат и заработает HTTPS.
6. Войдите по SSH: `ssh ubuntu@IP`. Проверьте `sudo tail -n 80 /var/log/cloud-init-output.log` и `sudo docker compose -f /opt/yasna/compose.yaml --project-directory /opt/yasna ps`.
7. Начальный пароль мастера создан случайно на VM, а не в публичных метаданных. Посмотрите его только в своём терминале через `sudo cat /opt/yasna/.env`; логин master. `.env` имеет закрытые права. Не публикуйте его.
8. В GitHub → Settings → Secrets and variables → Actions → Variables задайте `YASNA_SHARED_API_BASE=https://ВАШ-ДОМЕН` и запустите workflow «Публикация сайта». Не помещайте туда платёжные ключи. GitHub обслуживает интерфейс, а VM — защищённый API. Настройки `FRONTEND_ORIGIN=https://vosavasof.github.io` и `PUBLIC_APP_URL=https://vosavasof.github.io/Yasno/` уже создаются установщиком.
9. Восстановите резервную копию в кабинете мастера; проверьте остатки, оплаты и чеки. Старые ссылки родителей нужно перевыпустить на новый домен.

ЮKassa: сохраните Shop ID/ключ в настройках мастера на новом сервере; ключ зашифрован локальным секретом. Замените HTTP-уведомления в кабинете ЮKassa на `https://ВАШ-ДОМЕН/api/payments/webhook`. Проверьте тестовую оплату, возврат и состояние чека. Реальные деньги не переводите до проверки своего рабочего магазина и настроек НПД.

iPhone: откройте HTTPS-сайт в Safari, выберите «Поделиться → На экран Домой», запустите с экрана «Домой» (iOS 16.4+), войдите по своей ссылке, нажмите «Уведомления → Включить → Отправить проверку». Ответ сервера «принято push-службой» ещё не подтверждает доставку. Интерфейс ждёт подтверждения показа от Service Worker; фактический показ проверяется на телефоне. Исходящие запросы к push-службе Apple должны быть доступны VM.

Ежедневная полная копия БД выполняется в volume приложения. Она включает ключи ссылок и push. Это не отдельная внешняя резервная площадка: для защиты от потери VM дополнительно настройте приватное Object Storage/снимки средствами своего аккаунта. Не запускайте `terraform destroy` или удаление volume, пока не сохранена и не проверена внешняя копия.
