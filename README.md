# Ясна — приложение детской мастерской

**[Открыть работающий сайт](https://vosavasof.github.io/Yasno/)**

## Сайт на GitHub Pages

Интерфейс публикуется по адресу https://vosavasof.github.io/Yasno/ автоматически после изменения `main`. GitHub Pages обслуживает интерфейс, а общая база, авторизация и закрытые чеки работают через серверный API. Данные клиентов не записываются в репозиторий и не заменяются демонстрацией. Вход мастера — по паролю, родители — по персональным ссылкам. Для первого мастера используется отдельная одноразовая ссылка настройки, которая не публикуется в коде.

Конфигурация Pages собирается `scripts/build-pages.mjs`, публикация — `.github/workflows/pages.yml`. По умолчанию используется существующий сервер API. Его адрес можно заменить переменной репозитория `YASNA_API_BASE` (HTTPS). Сервер разрешает запросы только с настроенного адреса Pages. `backend/` содержит исходники облачного API и миграции. Серверная часть обновляется отдельно от статического интерфейса.

Локальный запуск и VPS по-прежнему используют сервер `server.mjs` на том же домене; `dist/config.js` по умолчанию не задаёт внешний API.


Самостоятельная версия для VPS: **без входа через ChatGPT и без обязательной CRM**. Node.js 24, SQLite, Docker Compose и HTTPS через Caddy. Светлая тема с фирменными жёлтыми и красными акцентами.

## Кто и как входит

- **Мастер** — по логину и паролю на главной странице. Только мастер создаёт расписание, отмечает посещения, принимает оплаты и управляет доступом.
- **Родитель** — по персональной ссылке, которую выдаёт мастер. Логин, пароль и аккаунт стороннего сервиса не нужны. Ссылка открывает только детей этой семьи.
- **Новый посетитель** — открывает `/#enroll`, оставляет заявку и контакты. Отправка заявки не создаёт доступ автоматически: сначала мастер связывается с родителем и подтверждает запись.

В карточке ребёнка нажмите **«Ссылка для родителя»**. Можно создать несколько ссылок для одной семьи, указать название и срок, копировать действующие ссылки повторно. Для проверки ссылки используйте другой профиль браузера, чтобы не переключать свою сессию мастера. По умолчанию ссылка действует 365 дней. «Перевыпустить» заменяет её новой, «Отозвать» закрывает доступ. Оба действия сразу прекращают и уже открытые по старой ссылке сессии.

Ссылка содержит случайный секрет и работает как ключ к кабинету семьи: передавайте её только нужному родителю. Секрет находится во фрагменте `#parent=…`, не попадает в обычный URL запроса и очищается из адресной строки после входа. Сессия хранится в HttpOnly-cookie. В базе хранится хеш секрета; восстановление ссылки мастером использует отдельный ключ из `data/parent-links.key`.

## Что работает

- Групповые и индивидуальные занятия, ручная длительность, вместимость и запись.
- Журнал посещений с однократным списанием и исправлением отметки.
- Абонементы, ручной учёт оплат, прикрепление чеков PDF/JPG/PNG до 2 МБ.
- Семейный кабинет: «Все дети» или отдельный ребёнок, ближайшие занятия, история, остатки, оплаты и чеки.
- Первичные заявки без кабинета: контакты → связь с родителем → подтверждение → выдача ссылки.
- Яркие уведомления и сохранение отметок «Прочитано»; обновление колокольчика каждые 30 секунд.
- Настраиваемые отмены, пропуски, тариф и порог напоминаний.
- CSV и резервные копии. Пустая рабочая база без демонстрационных клиентов.

Онлайн-эквайринг, фискализация и автоматическая отправка сообщений не подключены. Оплаты фиксирует мастер, чек формируется вне приложения и прикрепляется файлом. Лист ожидания доступен, автоматических рассылок предложений нет.

## Подготовка VPS (альтернативное размещение)

Нужны:

- Linux VPS с Docker Engine и Docker Compose v2; для небольшой мастерской достаточно начать с 1 ГБ памяти.
- Собственный домен или поддомен с A-записью на IP VPS.
- Открытые входящие порты 80 и 443. Порт 3000 приложения наружу не публикуется.

GitHub хранит исходный код. **GitHub Pages не запускает сервер Node.js и общую SQLite-базу**: опубликованный интерфейс обращается к отдельному серверному API. Ниже приведён альтернативный способ разместить весь проект на собственном VPS.

```bash
git clone https://github.com/vosavasof/Yasno.git
cd Yasno
cp .env.example .env
```

Отредактируйте `.env`:

```dotenv
SITE_DOMAIN=ваш-домен.ru
MASTER_LOGIN=master
MASTER_PASSWORD=ваш_длинный_случайный_пароль
```

Замените все примеры своими значениями. Пароль — от 12 символов. Значение-заглушка из `.env.example` специально не принимается приложением. Не коммитьте `.env` и не добавляйте его в образы.

```bash
chmod 600 .env
docker compose up -d --build
docker compose ps
```

Caddy получит HTTPS-сертификат автоматически, когда домен указывает на сервер. Откройте `https://ваш-домен.ru` и войдите мастером. Первичный пароль создаётся только при первом запуске пустой базы; изменение `.env` потом не сбрасывает существующий пароль.

Просмотр ошибок:

```bash
docker compose logs --tail=100 app
docker compose logs --tail=100 caddy
```

Проверка состояния: `https://ваш-домен.ru/api/health`.

## Обновление

```bash
git pull
docker compose up -d --build
```

База, сессии и ключ ссылок сохраняются в именованном Docker-volume `yasna_data`. **Не удаляйте volume и не запускайте `docker compose down -v`**, если данные нужны. Запускайте один экземпляр приложения с этой базой.

## Перенос из прежней версии

1. В прежнем рабочем сайте войдите мастером → «Отчёты» → «Скачать копию». Копия должна включать содержимое чеков.
2. Запустите эту версию на VPS и войдите новым логином мастера.
3. «Отчёты» → «Восстановить», выберите JSON и подтвердите замену.
4. Проверьте детей, расписание, остатки и чеки. Выдайте родителям новые персональные ссылки.
5. Переключайте родителей на новый адрес после проверки. Прежний сайт не удаляется этим репозиторием и сам по себе не переносится на VPS.

Доступы прежнего сервиса не переносятся: новая версия использует пароль мастера и семейные ссылки. Клиентские данные, оплаты, ключи ссылок и пароли **не входят в репозиторий**. Тестовые записи находятся только в `tests/fixtures.js`.

## Резервные копии

Перед каждым изменением приложение сохраняет предыдущую версию данных (последние 30 копий) в `data/backups`. Кнопка в «Отчётах» выгружает JSON клиентов, записей, оплат и чеков. JSON не содержит паролей и ключей доступа.

**Полная серверная копия**, включая доступы и ключ родительских ссылок:

```bash
docker compose exec -T app npm run backup
```

Создаётся папка `data/backups/full-…` с согласованной копией `yasna.sqlite` и `parent-links.key`. Копирование SQLite через `VACUUM INTO` допускается во время работы приложения. Сохраняйте полные копии вне VPS:

```bash
docker compose cp app:/app/data/backups ./backups
```

Для автоматизации настройте эту команду резервирования в планировщике сервера. Копия на том же VPS не защищает от потери сервера.

Полное восстановление выполняйте при остановленном приложении: сначала сохраните текущие данные, затем замените базу и ключ из одной копии в volume. Старые `yasna.sqlite-wal` и `yasna.sqlite-shm` при остановленном приложении не переносите поверх восстановленного снимка. Файлы должны быть доступны пользователю `node` (UID 1000). После запуска проверьте вход мастера и одну семейную ссылку.

## Сброс пароля мастера

Команда `add-user` предназначена только для мастера; родительских паролей здесь нет.

На сервере с обычным Node.js:

```bash
read -rp 'Логин мастера: ' USER_LOGIN
read -rsp 'Новый пароль: ' USER_PASSWORD
export USER_LOGIN USER_PASSWORD
USER_ROLE=master node server.mjs add-user
unset USER_PASSWORD
```

Для Docker после экспорта переменных:

```bash
export USER_ROLE=master
docker compose exec -e USER_LOGIN -e USER_PASSWORD -e USER_ROLE app node server.mjs add-user
unset USER_PASSWORD
```

Смена пароля закрывает существующие сессии этого мастера.

## Локальная разработка

Node.js 24+. Для запуска серверу не нужны npm-зависимости:

```bash
read -rsp 'Пароль мастера (от 12 символов): ' MASTER_PASSWORD
export MASTER_PASSWORD
COOKIE_SECURE=false PUBLIC_ORIGIN=http://127.0.0.1:3000 node server.mjs
```

Откройте `http://127.0.0.1:3000`. Небезопасные cookies допускаются только для локального HTTP; Docker-конфигурация использует HTTPS и Secure-cookie.

Проверки:

```bash
npm ci
npm test
```

Проверяются изоляция семей, запрет родительского входа по паролю, создание/копирование/отзыв/перевыпуск/истечение ссылок, прекращение старых сессий, сохранение доступа после перезапуска, полная резервная копия, первичная запись, списания и формы интерфейса. GitHub Actions запускает тесты на Node.js 24.

## Расписание, родители и перенос данных

Перенос и отмена занятий доступны в расписании и журнале, перенос отдельной записи — также родителю по правилам отмены. Родители и дети добавляются отдельно и убираются в архив с сохранением истории; удаление родителя отзывает ссылки семьи. Импорт из «МойКласс» поддерживает CSV/XLSX с выбором столбцов, предварительной проверкой и защитой от дублей. [Инструкция](docs/operations.md).

## Онлайн-оплата

ЮKassa подключается в кабинете мастера: **Настройки → Подключение ЮKassa**. Ключ вводится там и хранится зашифрованным на сервере. Родитель выбирает ребёнка, оплачивает на стороне ЮKassa, а занятия начисляются после серверного подтверждения. Тестовый режим не меняет рабочий баланс. [Подключение, проверки и отдельная автоматизация «Мой налог»](docs/yookassa.md).

## Структура

На телефоне доступны нижняя навигация, выдвижное меню, карточки клиентов и оплат вместо широких таблиц, увеличенные поля и кнопки. Логотип на белом фоне загружается в WebP (около 36 КБ) с PNG-резервом. Шрифты системные, без запросов к Google Fonts.

- `server.mjs` — HTTP API, SQLite, пароль мастера, сессии и ссылки родителей.
- `dist/` — интерфейс и локальные ресурсы; это исходные HTML/JS/CSS, отдельная сборка не нужна.
- `scripts/backup.mjs` — полная согласованная резервная копия.
- `tests/` — автоматические проверки с вымышленными данными.
- `Dockerfile`, `compose.yaml`, `Caddyfile` — развёртывание на VPS.
- `data/` — рабочие данные, создаются при запуске и исключены из Git.
